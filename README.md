# うまアプリ（JRA 馬券収支シミュレーター）

「2026年1月〜現在まで、ルメール騎手の全騎乗を単勝100円ずつ買っていたら収支はいくら？」のような計算をする Web アプリです。

- データ元: JRA 公式サイト（www.jra.go.jp の「過去レース結果」：着順・人気・払戻金）
- **スマホ版（GitHub Pages）**: https://mktyou-lgtm.github.io/umaapp/ — PC 不要。データは毎日 18:30（日本時間）に自動更新
- **PC 版（ローカル）**: 検索時に、指定期間で未取得の開催だけを自動で取得してから計算します（差分更新）。データはローカルの SQLite（`data/jra.sqlite`）に保存されます

## スマホ版（GitHub Pages）の仕組み

`.github/workflows/update.yml` が毎日 18:30（日本時間）に次の処理を行います。手動で実行するときは GitHub の Actions タブから「データ更新とサイト公開」→ Run workflow。

1. 前回までのデータベースを Actions のキャッシュから復元
2. JRA 公式サイトから新しい開催の分だけ取得（`npm run sync`）
3. 計算に必要な列だけを `site/data/data.json` に書き出し（`npm run export`）、画面ファイルと一緒に GitHub Pages へ公開

画面（`public/index.html`）は、API があればローカル版、無ければ `data/data.json` を読み込んでブラウザ内で計算する静的版として動きます。計算ロジックは `public/sim.js` を両方で共有しています。

注意:

- 競馬データはリポジトリには含めず、公開ページにだけ載せています。公開ページは URL を知っていれば誰でも見られます
- キャッシュが消えた場合（7 日間使われなかったときなど）は、次回の実行で 2026 年分を最初から取り直します（20〜30 分）
- 60 日間リポジトリに動きが無いと、GitHub が定期実行を自動で止めます。止まった場合は GitHub からのメールか Actions タブから再開してください

公開する前の確認は次の手順でできます。

```bash
npm run export
```

```bash
npm run preview
```

http://localhost:4000 で公開版と同じ画面を確認できます。

## PC 版の起動

Node.js 22.13 以上（推奨 24）が必要です。

```bash
npm install
```

```bash
npm start
```

ブラウザで http://localhost:3939 を開きます。

JRA 公式サイトは 1 開催（1 日・1 場）の全 12 レースの結果と払戻が 1 ページにまとまっているため、2026 年分（約 250 開催・3,300 レース）でも約 500 回のアクセスで取得できます。サーバーへの負荷を避けるため 2.5 秒に 1 回程度のアクセスにしているので、初回は 20〜30 分ほどかかります。一時的にアクセス制限（HTTP 503 など）を受けた場合は、自動で数分〜30 分待ってから再開します。取得中も、取得済みの分で途中経過を表示します。2 回目以降は新しい開催の分だけを取得します。

ターミナルからまとめて取得しておくこともできます。

```bash
npm run sync -- 2026-01-01 2026-11-19
```

## できること

- 対象: 騎手 / 調教師 / 馬（名前の部分一致。入力中に候補をプルダウン表示）
  - ひらがなでも検索可（「るめーる」→ C.ルメール、「えんぶろ」→ エンブロイダリー）
  - 騎手・調教師は読み仮名でも一致（「かわだ」→ 川田将雅）。読みは JRA の騎手・調教師名鑑から取得（初回のみ約 15 分、以降は新しい人の分だけ）
- 期間: 任意の開始日〜終了日
- 券種: 単勝 / 複勝、1 レースあたりの購入額
- 結果: 収支・回収率・的中率・着別度数・最高払戻、累積収支グラフ、月別収支（グラフ / 表）、レース一覧

## 出馬表

画面上部の「出馬表」で、JRA 公式サイトに公開中の出馬表（通常は木〜金曜に週末分）を表示します。

- 日付・競馬場・レースを選ぶと、出走馬ごとに次を表示
  - 単勝オッズと人気（取得時点）、出走取消・除外
  - 騎手・調教師の勝率・複勝率・単勝回収率（範囲: 同じ競馬場・コース・距離 / 同じコース・距離 / 同じコース / 全レース）
  - 馬の全成績・同条件成績と近 5 走の着順
- 集計はレース前日までの過去 1 年。各項目の上位 3 頭を強調、10 件未満は薄く表示
- 騎手・調教師・馬の名前をタップすると、同じ条件で収支シミュレーターを開く
- スマホ版は毎日 18:30 と土日月の朝 8:00 に更新。PC 版は「出馬表・オッズを今すぐ更新」で取り直せる（自動では 30 分に 1 回まで）

### 予想勝率（public/model.js）

- **能力モデル**: オッズを使わず、騎手・調教師の勝率、馬の近走（着順・勝ち馬とのタイム差・スピード指数・上り 3F の順位・4 コーナー位置・人気）、クラスや距離の変化、間隔、馬齢・性別、斤量、枠から勝率を推定（レース内 softmax の条件付きロジット）
- **総合モデル**: 能力モデルの勝率とオッズから見た勝率を組み合わせたもの。全馬のオッズが出ているときに使う
- 特徴量はそのレースより前のデータだけで作る。検証は「その時点までで学習 → 次の 28 日間を予想」をくり返す方式で、結果は画面下の「予想モデルの検証結果」に表示
- 検証では総合モデルの精度はオッズとほぼ同じで、期待値で買っても回収率 100% は超えていない（過去成績はほぼオッズに織り込まれている）
- **当たる確率が高い買い目**: 予想勝率から券種（単勝・複勝・ワイド・馬連・馬単・3連複・3連単）ごとの的中確率を計算し、確率の高い順に 3 点表示。2・3 着はハービルの方法を補正（勝率を 2 着は 0.85 乗、3 着は 0.70 乗して平らにする）して計算。過去レースで各券種の最も確率の高い買い目を毎レース買った場合の的中率・回収率も検証結果に表示

## 計算ルール

- 払戻は JRA 公式の払戻金（100 円あたり）を使用（同着の払戻も正しく反映）
- 出走取消・競走除外は返還のため購入数に含めない
- 競走中止・失格はハズレ扱い
- JRA 10 場のレースのみ（地方・海外は含まない）
- 公式の成績表には単勝オッズの列が無いため、レース一覧のオッズは勝ち馬のみ（払戻金 ÷ 100）表示

## 仕組み

JRA のページは URL ではなく `cname`（末尾に 2 桁のチェック値付き）を POST して開く仕組みなので、URL を組み立てずにページ内のリンクを辿ります。

1. 月別の開催一覧（当月 → 「前月」リンクを辿って過去の月へ）
2. 開催ごとのレース選択ページ → 全レース結果ページへのリンク
3. 全レース結果ページ（12 レース分の着順・騎手・調教師・人気・払戻金）

## 注意

JRA 公式サイトのデータを個人的に利用するためのツールです。取得データの再配布や、短い間隔での大量アクセスは行わないでください。アクセス間隔は環境変数 `UMAAPP_INTERVAL_MS`（既定 2500ms）で変更できます。

ノートン等のセキュリティソフトが HTTPS 通信を検査している環境向けに、起動スクリプトで `--use-system-ca`（Windows の証明書ストアを利用）を指定しています。

## 構成

| ファイル | 役割 |
|---|---|
| `src/jra.js` | JRA 公式サイトの開催一覧・結果ページの取得とパース |
| `src/sync.js` | 期間指定の差分同期 |
| `src/query.js` | 収支計算（ローカル版。DB から取り出して `public/sim.js` で集計） |
| `src/server.js` | HTTP サーバー / API |
| `public/index.html` | 画面（ローカル版・静的版 共通） |
| `public/sim.js` | 収支計算ロジック（ローカル版・静的版 共通） |
| `src/dataset.js` | ブラウザ内計算用のデータ一式（静的版の data.json・PC 版の出馬表画面で共通） |
| `scripts/export.js` | 静的サイト（`site/`）の書き出し |
| `scripts/serve-static.js` | 静的サイトの確認用サーバー |
| `.github/workflows/update.yml` | 毎日のデータ更新と GitHub Pages への公開 |
